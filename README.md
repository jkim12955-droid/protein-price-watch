# 단백질 가격 비교기

한국소비자원 참가격의 생필품 가격에 식약처 식품영양성분을 이어 붙여, 단백질 1g을 가장 싸게 주는 상품을 찾는 자동화 파이프라인이다. 매일 새 조사분이 있는지 확인해 받아두고, 월요일 아침 9시에 리포트를 만들어 슬랙으로 보낸다. 사람이 손대지 않아도 돈다.

장을 볼 때마다 용량 대비 가격과 100g당 단백질을 머릿속으로 따지던 일을 코드로 옮긴 것이다. 매대 앞에서 두세 개를 비교하던 것이, 매번 식품 457개를 훑어 그중 단백질을 싸게 주는 순서로 줄 세운 결과를 받는 것으로 바뀐다.

## 무엇이 나오나

리포트 한 장이다. 최근 조사분 기준으로 순위에 올릴 수 있었던 상품은 67개고 그중 위에서 20개, 늘 사던 닭가슴살보다 싼 대안, 따로 지켜보는 여덟 품목의 변화, 지금 할인 중인 것, 자동 점검 결과표, 그리고 못 하는 것의 목록이 들어 있다. 예시는 reports/ 폴더에 있다.

## 데이터

| 소스 | 제공 | 무엇을 주나 | 주기 | 이용조건 |
|---|---|---|---|---|
| [생필품 가격 정보](https://www.data.go.kr/data/15158701/openapi.do) | 한국소비자원 참가격 | 상품 604개의 판매점 630곳 가격, 할인 여부 | 격주 금요일 조사 | 공공저작물 제1유형(출처표시) |
| [식품영양성분DB](https://www.data.go.kr/data/15127578/openapi.do) | 식품의약품안전처 | 식품별 100g당 단백질 등 | 월 1회 갱신 | 제한 없음 |

둘 다 공공데이터포털 오픈API 다. 참가격은 공공저작물 제1유형이라 출처를 밝히면 저장과 재배포가 된다. 그래서 받은 원본을 `data/raw/` 에 그대로 두고 DB 를 언제든 다시 만든다.

`data/raw/` 의 판매점 정보는 사업장 정보다. 630곳 전부 사업장 유선번호이고 개인 연락처나 이름은 들어 있지 않다. 상호와 상표는 공공누리 이용허락이 덮는 범위가 아니라, 참가격이 공개한 그대로 가격 비교 목적으로 인용한 것이다.

소재를 정하기 전에 네이버 검색 API 와 유튜브 API 를 먼저 검토했다가 접었다. 네이버는 이용약관이 검색 결과의 저장을 막고 쇼핑 검색 자체가 2026년 8월에 종료됐다. 유튜브는 API 데이터를 30일 넘게 보관하거나 집계하는 것을 금지한다. 둘 다 "매주 쌓아서 추세를 본다" 는 이 프로젝트의 전제와 정면으로 어긋난다. 그 판단 과정은 docs/build-log.md 에 있다.

## 어떻게 도나

```
매일 09:30    collect   새 조사일이 생겼나 확인. 있으면 상품 604개의 가격을 받아 원본 그대로 저장
              load      원본 전체를 SQLite 에 다시 넣는다. 같은 것을 두 번 넣어도 안 깨진다
              match     새로 생긴 상품만 식약처 DB 에 잇는다. 나머지는 캐시에서 읽어 호출이 0회다
              qa        열 가지를 점검. 임계값을 넘으면 여기서 멈춘다
월요일 09:00  report    새 조사분이 있으면 리포트를 만든다
              notify    슬랙에 요약 한 줄과 링크
```

점검이 실패하거나 어느 단계든 죽으면 GitHub 이 저장소 주인에게 실패 메일을 보내고, 슬랙에도 실행 기록 링크가 한 줄 간다. 실패해도 그때까지 받은 원본과 점검표는 커밋한다. 무엇을 보고 실패했는지가 남아야 고칠 수 있다.

단계마다 명령이 따로 있어서 깨진 단계만 다시 돌릴 수 있다.

```
python pw.py collect [--date 20260828] [--force]
python pw.py load
python pw.py match      # 상품에 영양 항목 잇기. 처음 한 번, 상품이 바뀌면 --refresh
python pw.py qa
python pw.py report --force --any-day
python pw.py notify --report reports/2026-W35.md
python pw.py calls      # 조사일별로 실제 쓴 API 호출 수 (하루 한도 2,000회)
```

파이썬 3.11 이상이면 된다(CI 는 3.12). 표준 라이브러리만 쓰므로 설치할 것이 없다. 키는 공공데이터포털에서 두 API 를 신청해 받은 일반 인증키(디코딩)를 `.env` 에 넣는다(`.env.example` 참고). 계정당 키가 하나라 두 값이 같아도 정상이다. GitHub Actions 에서는 Secrets 에서 읽는다.

키 없이 구조만 보려면 `data/raw/` 의 원본이 이미 저장소에 있으므로 `python pw.py load` 부터 `report` 까지 그대로 돌아간다. 새로 수집하는 `collect` 와 처음 매칭하는 `match` 에만 키가 필요하다.

맥에서 인증서 오류(`CERTIFICATE_VERIFY_FAILED`)가 나면 파이썬이 시스템 인증서를 못 찾는 것이다. 한 번은 검증 없이 재시도하도록 해뒀고, 처음부터 끄려면 `PW_INSECURE_SSL=1` 을 준다. CI 에서는 이 우회가 아예 켜지지 않는다. 조용히 검증을 끄면 중간에 누가 끼어들어도 모르기 때문이다.

## 가장 어려웠던 것

상품명과 식약처 식품명이 다르다. 참가격은 "동원참치 라이트스탠다드(150g)" 이고 식약처는 브랜드 제품이면 같은 이름으로, 원재료면 "돼지고기_삼겹살_생것" 처럼 적는다. 세 갈래로 잇는다. 신선식품 축산·수산은 사람이 짝을 지어 `config/manual_match.json` 에 두고, 가공식품은 상품명에서 용량과 브랜드를 떼어낸 변형으로 검색해 이름이 같은 것을 먼저 찾고, 없으면 단어가 75% 이상 겹치면서 그 소분류에 정해둔 규칙과 단백질 상식 범위를 모두 통과하는 항목만 고른다. 마지막으로 소분류 기본 항목을 쓰는 갈래를 두었는데 실제 실행에서는 한 번도 쓰이지 않았다. 앞의 두 갈래가 못 이으면 미매칭으로 남기는 편이 틀린 짝을 만드는 것보다 낫다고 봐서 그대로 뒀다.

느슨하게 이었을 때 무슨 일이 생기는지는 겪어봤다. 처음에는 겹침 기준만 보고 이었더니 칠성사이다 제로가 단백질 1위로 올라왔고 밀가루가 상위를 채웠다. 순위에 올릴 소분류를 27개로 못 박고, 부분 매칭은 규칙이 있는 분류에서만, 분류마다 단백질 상식 범위를 두고 나서야 순위가 말이 됐다. 못 이은 비율은 그 자체로 품질 지표다. 지금은 순위 대상 98개 중 83개를 이었다. 결과와 미매칭 목록은 docs/match_report.md 에 있다.

## 사람이 정하는 것

기계는 수집하고 적재하고 계산하고 점검하고 리포트를 쓴다. 사람이 정하는 것은 셋이다. 순위에 올라와도 실제로 먹지 않는 상품을 빼는 규칙(`config/categories.json`), 늘 사는 닭가슴살의 가격(`config/baseline.json`), 점검 임계값(`config/qa_thresholds.json`). 계산에 AI 를 쓰지 않는다. 단백질 1g당 가격은 나눗셈이라 같은 입력에 항상 같은 결과가 나오고 비용이 0원이다.

## 증거

- docs/build-log.md : 단계마다 무엇을 했고 무엇이 깨졌는지. 첫 실행 숫자.
- docs/match_report.md : 매칭률과 미매칭 목록, 자동 매칭 검토용 표.
- docs/qa/ : 점검표. 하루에 한 장씩 날짜로 남는다.
- data/raw/ : 조사일별 원본 JSON(압축). 이걸로 DB 를 언제든 다시 만든다.
- 커밋 히스토리 : 매주 리포트 커밋이 쌓인 것이 무인 운영의 기록이다.

## 못 하는 것

- 하림 훈제 닭가슴살은 참가격에 없어 가격을 사람이 넣는다.
- 크레아틴과 프로틴 파우더 같은 건강기능식품은 참가격이 조사하지 않는다.
- 오징어, 연어, 참조기는 식약처 DB 에 원재료 항목이 없어 순위에서 뺐다.
- 쇠고기 불고기는 부위가 특정되지 않아 앞다리 값으로 근사했다. 계란은 설명이 빈 상품에 개당 52g 을 썼다.
- 자동·부분 매칭은 틀릴 수 있다. 의심스러우면 검토용 표를 본다.

## 구조

```
pw.py                 명령줄 진입점
pipeline/
  api.py              두 API 클라이언트 (재시도, 호출 수 집계)
  collect.py          새 조사일 탐지, 원본 저장
  load.py             SQLite 멱등 적재, 원본 대조
  quantity.py         묶음 무게 환산 (100g당 가격의 분모)
  match.py            상품에 영양 항목 잇기
  metrics.py          상품별 지표 (리포트와 점검이 같이 쓴다)
  qa.py               열 가지 점검
  report.py           주간 리포트
  notify.py           슬랙
config/               사람이 정한 것들
.claude/skills/protein-qa/   점검 스킬
.github/workflows/pipeline.yml
```

## 출처와 라이선스

- 생필품 가격 정보: 한국소비자원 참가격, 공공데이터포털 제공. 공공저작물 제1유형(출처표시).
- 식품영양성분DB: 식품의약품안전처, 공공데이터포털 제공.

코드는 MIT 다(LICENSE 참고). `data/raw/` 아래 원본은 위 두 기관의 공공데이터이며 출처 표시 조건으로 그대로 둔 것이다.

이 프로젝트는 SeSAC 데이터 분석 과정의 업무 자동화 포트폴리오 워크북을 따라 만들었다. 소재 선정부터 설계까지의 워크북은 별도 파일로 있다.
